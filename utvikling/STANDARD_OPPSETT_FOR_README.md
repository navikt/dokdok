# readme.md standard

## Introduksjon

Dette dokumentet definerer Team Dokumentløsninger readme.md for apper teamet er ansvarlig for.

Dokumentet beskriver hvordan en readme.md skal se ut, hvordan den skal struktureres og hvilke prinsipper teamet skal forholde seg til.

I all hovedsak er readme dokumentet ment for å gjøre det lettere for neste utvikler. Dokumentet trenger ikke å være overflødig av informasjon, men konkret og lett leslig. Ønsket er at utvikler skal være klar til å utvikle etter å ha lest dokumentet.


Se til readme.md i dette prosjektet på oppsettet for [Referanse](https://github.com/navikt/doknotifikasjon).

readme er delt i 5 kategorier

* [1. Funksjonelle Krav](#1-funksjonelle-krav)
* [2. Begrensninger](#2-begrensninger)
* [3. Distribusjon av tjenesten (deployment)](#3-distribusjon-av-tjenesten-deployment)
* [4. Utviklingsmiljø](#4-utviklingsmilj)
* [5. Drift og støtte](#5-drift-og-sttte)

# 1. Funksjonelle Krav
Kort forklaring av applikasjon, kan bruke et utdrag fra confluence. Legg også med link til confluence om det er tilgjengelig.

# 2. Begrensninger
Kort beskrivelse av begrensinger for tjenesten. En begrensinger kan være at en brukeren spør tilgang til et dokument, men har ikke rettigheter til å se heile dokumentet.

# 4. Utviklingsmiljø

Start med å skrive forutsetninger for å utvikle og teste lokalt, dette gjelder teknologier og verktøy som utvikler må ha kunskap til for å kunne utvikle applikasjonen.

Neste steg er å skrive om hvordan man setter opp applikasjonen for lokalt utvikling. Dette gjelder system variabler, hvilken profiler som må settes og andre krav. 

Husk å ta med link til vault om du må sette system variabler.

# 5. Drift og støtte

Link til Kibana og hvordan man kobler seg til poden på kubectl og evt andre overvåkningsverktøy.
