# readme.md standard

## Introduksjon

Dette dokumentet definerer Team Dokumentløsninger reeadme.md for apper teamet er ansvarlig for.

Dokumentet beskriver hvordan en readme skal se ut, hvordan den skal struktureres og hvilke prinsipper teamet skal forholde seg til.

I all hovedsak er readme dokumentet ment for å gjøre det lettere for neste utvikler. Dokumentet trenger ikke å være overflødig av informasjon, men konkret og lett leslig. Ønsket er at utvikler skal være klar til å utvikle etter å ha lest dokumentet.


Se til readme.md i dette prosjektet på oppsettet for [Referanse](https://github.com/navikt/doknotifikasjon).

readme er delt i 5 kategorier

* [1. Funksjonelle Krav](#1-funksjonelle-krav)
* [2. Begrensninger](#2-begrensninger)
* [3. Distribusjon av tjenesten (deployment)](#3-distribusjon-av-tjenesten-deployment)
* [4. Utviklingsmiljø](#4-utviklingsmilj)
* [5. Drift og støtte](#5-drift-og-sttte)

# 1. Funksjonelle Krav
Kort forklaring av application, kan bruke et utdrag fra confluence. Legg også med link til confluence om det er tilgjengelig.

# 2. Begrensninger
Kort beskrivelse av begrensinger for tjenesten

# 4. Utviklingsmiljø

Start med å skrive forutsetninger for å utvikle og teste lokalt, dette gjelder teknlologier og verktøyer som utvikler må ha kunskap til for å kunne utvikle applikasjonen.

Nester er å skrive om hvordan man setter opp for lokalt utvikling. Ta med link til vault om du må sette system variabler og profil.

# 5. Drift og støtte

Link til Kibana og hvordan man kobler seg til poden på kubectl og evt andre overvåknings verktøy.
